\section{Experiments}
\label{sec:experiments}

\subsection{Setup}
We evaluate in Gazebo Harmonic (\texttt{gz-sim 8}) bridged to ROS 2 via
\texttt{ros\_gz\_bridge}. Four scenarios are tested: warehouse corridor,
forest clearing, indoor SLAM dropout (textures masked mid-flight), and
low-texture wall. Each scenario is run for 60\,s with synchronized
30\,Hz monocular images, 50\,Hz 1D range, 4-channel 48\,kHz audio, and
200\,Hz IMU. Nodes are launched via
\texttt{ros2 launch gps\_denied\_drone sim.launch.py}.

\subsection{Hardware target}
Onboard compute is a Raspberry Pi 5 (8\,GB) with the Raspberry Pi
AI HAT+ (Hailo-8). Pi\,5 idle power is $\sim$3\,W; sustained four-core
load is 9--12\,W; the Hailo-8 contributes $\sim$5\,W typical and up to
8\,W peak under inference. Combined drone-stack budget is
\textbf{15--18\,W}, which is $\sim$10\% of the motor power for a
500\,g class quadrotor in hover. CPU shares are approximately
ORB-SLAM3 1.5 cores, acoustic processing 0.5 core, MPC 0.3 core,
DDS 0.2 core, and SLM advisory $\sim$1 core in burst.

Gemini Nano runs only on Pixel/Tensor hardware via Android AICore. On
Pi\,5 we deploy a Gemini Nano-class SLM (Gemma\,3\,1B, Q4\_K\_M, via
\texttt{llama.cpp}) in the same advisory role. We report wall-clock
SLM tick latency under contention with SLAM and MPC running. The full
breakdown is in \texttt{docs/hardware\_target.md}.

\subsection{Ablations}
We compare five configurations: full system; no range; no
perception-cost; no reasoner; classical-only. Configuration files are
in \texttt{experiments/configs/ablations.yaml}.

\subsection{Metrics}
Absolute trajectory error (ATE-RMSE), mission completion rate, minimum
clearance, MPC solve time, and Gemini Nano latency.
